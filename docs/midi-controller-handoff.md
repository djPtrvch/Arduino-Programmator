# MIDI-контроллер: итоги и задел для следующего этапа

Документ для передачи контекста в новую ветку или новый чат с ИИ. Здесь всё, что уже сделано в репозитории `djPtrvch/Arduino-Programmator`, что выяснили на практике и что планируется дальше.

---

## 1. Цель следующего этапа

USB-MIDI контроллер:

- **16 энкодеров EC11 с нажатием.** Бесконечные, значение CC 0–127, ускорение при быстром вращении, обратная связь от программы.
- **LED-кольца вокруг каждого энкодера.** Показывают текущее значение, в том числе пришедшее из программы.
- **Дополнительные кнопки** (количество уточнить).
- **Конфигуратор в браузере.** Настройка каждого энкодера и кнопки без перепрошивки, пресеты.
- **Печатная плата**, файлы для заказа на JLCPCB или PCBWay.

---

## 2. Окружение пользователя

- **Устройства:** только iPad и Android (Pixel 7). Компьютера нет.
- **Код** пишет ИИ (Claude Code), собирает GitHub Actions, публикует GitHub Pages.
- **Прошивка** заливается **из Chrome на Pixel 7 по USB-C** (WebUSB). Samsung Internet и Safari не подходят: там нет WebUSB и Web MIDI.
- **Плата:** клон **Pro Micro** (ATmega32U4, 5 В / 16 МГц, USB-C, загрузчик Caterina). Кнопки RESET нет, сброс делается замыканием RST на GND.
- **Есть:** мультиплексоры **CD74HC4067** (модули), энкодеры **EC11**, потенциометры B10K, макетная плата.
- **Правила работы:** пушить сразу в `main` (без pull request), после пуша проверять GitHub Actions. Интерфейсы двуязычные (RU/EN). Отвечать коротко, по-русски.

## 4. Программатор (как устроен и что выяснили)

1. Chrome показывает список USB-устройств (`requestDevice`, фильтр пустой: у клонов бывает другой VID).
2. Если плата не в загрузчике, программатор делает «1200-baud touch»: SET_LINE_CODING 1200 + DTR=0. Плата перезагружается в Caterina, и **это новое USB-устройство**.
3. **«Шаг 2 из 2»:** у загрузчика нет серийного номера, поэтому Chrome **каждый раз** заново просит выбрать плату. Загрузчик ждёт 8 секунд. Если не успели, программатор повторяет перезагрузку (до 3 раз).
4. AVR109: `S` (CATERIN), `s` (сигнатура), `P`, `e`, `A`+`B`…`F` (запись страниц по 128 байт), `g` (проверка), `L`, `E`.
5. Пишется только программа (`.ino.hex`, до 28 672 байт). Загрузчик не трогается.

**Что выяснили на практике:**
- В Samsung Internet USB «не видно», в Chrome работает.
- Если плата «зависла», нужно **два раза быстро замкнуть RST на GND** и сразу нажать «Прошить».
- GitHub Pages кэширует файлы до 10 минут. Программатор добавляет `?v=<commit>` к файлам прошивки и `?t=` к `manifest.json`.
- Прошивка занимает около 3 секунд.

## 5. Железо: что выяснили на макетке

- **Пины Pro Micro, левый ряд от USB:** `RAW, GND, RST, VCC, A3, A2, A1, A0, 15, 14, 16, 10`. Правый ряд: `TX, RX, GND, GND, 2, 3, 4, 5, 6, 7, 8, 9`.
- Провода легко ставятся **на ряд мимо**. Проверка: перемычка с входа на GND/VCC должна дать 0/127 на MIDI-мониторе.
- У длинных макеток **шины питания разорваны посередине**.
- **Неподключённые аналоговые входы и входы мультиплексора «плавают»** и повторяют соседний вход. Это нормально. Для потенциометров свободные входы лучше соединить с GND.
- Дрожание потенциометров убрано в прошивке: усреднение 8 чтений, холостое чтение после переключения, экспоненциальный фильтр и гистерезис ±4 единицы АЦП вокруг шага CC.

## 6. Прошивка `encoders16`

### Подключение
```
S0–S3 всех трёх CD74HC4067 → пины 2, 3, 4, 5   EN → GND
Мультиплексор 1: выводы A энкодеров → SIG → пин 6
Мультиплексор 2: выводы B энкодеров → SIG → пин 7
Мультиплексор 3: кнопки энкодеров   → SIG → пин 8
Энкодер N → входы C(N−1); средний вывод C энкодера и 2-я ножка кнопки → GND
Подтяжка — внутренняя (INPUT_PULLUP на 6/7/8), резисторы не нужны
```
Свободны: 0, 1, 9, 10, 14, 15, 16, A0–A3.

### Логика
- Опрос: выбор канала, пауза 10 мкс, чтение A/B/SW. Полный цикл около 0,3 мс.
- Квадратурный декодер по таблице. Тип EC11: 4 перехода на щелчок (20 щелчков на оборот), 2 перехода (30 щелчков) или 1.
- Ускорение: интервал между щелчками меньше 15 мс → шаг 6, меньше 35 мс → 3, меньше 70 мс → 2.
- Режимы поворота: **абсолютный** 0–127, **относительный 64±n** (Binary Offset), **относительный 1/127** (Two's Complement).
- Кнопка: CC 127/0, нота (Note On/Off) или ничего. Режим **моментальный** или **переключатель**. Антидребезг 5 мс.
- **Обратная связь:** входящий CC на номер/канал энкодера задаёт текущее значение (абсолютный режим). Входящий CC (≥64 — вкл) или нота задаёт состояние кнопки-переключателя.
- По умолчанию: энкодер N → CC N−1, канал 1; кнопка N → CC N−1, канал 2, моментальная.

### Настройки (EEPROM)
- Метка `E N C` + версия `1` по адресам 0–3, затем `struct Config` с адреса 4.
- `Config` = `detentSteps, reverse` + 16 × `EncConfig` (8 байт):
  `channel, cc, mode, accel, btnType, btnChannel, btnNumber, btnMode`. Всего 130 байт.
- **Порядок байт одинаков в прошивке и конфигураторе (`ENC_FIELDS`).** При изменении формата поднять версию.

### SysEx-протокол
`F0 7D 4D <cmd> [данные] F7` (7D — некоммерческий ID, 4D — устройство)

| Запрос | Ответ |
|---|---|
| `01` | `02 <версия> <число энкодеров> <размер настроек: 2 байта по 7 бит>` |
| `03` | `04 <130 байт настроек>` |
| `05 <130 байт>` | `06 <0 — сохранено / 1 — ошибка>` |
| `07` (сброс по умолчанию) | `06 00` |
| `08` | `09 <16 текущих значений>` |

Отправка SysEx по USB-MIDI: пакеты CIN 0x4 (начало/продолжение), 0x5/0x6/0x7 (конец на 1/2/3 байтах).

### Как проверялось
Логика проверена только на компьютере: заглушки Arduino, g++, имитация вращения, кнопок и SysEx. **На реальных EC11 ещё не запускалась.**

## 7. Конфигуратор (`configurator/`)

- Подключение: `requestMIDIAccess({sysex:true})`. Опрашивает все MIDI-выходы командой `01` и находит контроллер по ответу.
- Сетка 4×4 с кольцами-индикаторами. Живое значение при вращении, подсветка при нажатии.
- Редактор энкодера: режим, канал, CC, ускорение. Нажатие: тип, режим, канал, номер.
- «Применить ко всем (номера по порядку)», тип EC11, инверсия направления.
- Пресеты в JSON (`format: "encoders16"`), сброс по умолчанию, «Прочитать» / «Записать».
- RU/EN общий с программатором (`localStorage.lang`).

## 8. План: LED-кольца и кнопки

### LED-кольца
- **Рекомендация:** адресные светодиоды **WS2812B-2020** или **SK6812-MINI-E**, по 9–12 вокруг энкодера, **на печатной плате с заводским монтажом** (JLCPCB PCBA). 16 × 11 = 176 штук, примерно 10–20 $.
- Альтернатива: готовые кольца на 8–12 светодиодов (диаметр 30–37 мм), но тогда шаг энкодеров около 40 мм.
- Управление: **1 пин** (например, 9 или 10), библиотека FastLED или Adafruit_NeoPixel.
- **Питание:** USB даёт 500 мА. Ограничить яркость в прошивке, зажигать только индикатор значения. Помнить, что один светодиод на полной яркости потребляет до 60 мА.
- **Память:** 176 × 3 = 528 байт RAM из 2,5 КБ у 32U4. Влезает, но впритык вместе с MIDI и буферами SysEx.
- **Время:** обновление 176 светодиодов WS2812 занимает около 5,3 мс с выключенными прерываниями, в это время энкодеры не опрашиваются. Обновлять только при изменениях и порциями. Если не хватит, рассмотреть RP2040 вместо 32U4: он прошивается файлом `.uf2` через «Файлы» на Android, и PIO выводит светодиоды без блокировки.
- Конфигуратор: добавить цвет и режим кольца (точка, заполнение, от центра).

### Дополнительные кнопки
- До 16 кнопок: **4-й CD74HC4067**, SIG на свободный пин (например, 10), S0–S3 общие. Кнопка замыкает вход на GND.
- Несколько кнопок можно подключить напрямую на свободные пины (0, 1, 14, 15, 16, A0–A3).
- В `struct Config` добавить блок кнопок (тип, канал, номер, режим) и поднять версию EEPROM.

### Печатная плата
- KiCad: схема + разводка. В GitHub Actions: DRC через `kicad-cli`, Gerber, сверловка, BOM и файл расстановки для PCBA, картинки платы для проверки с iPad.
- **Решить до проектирования:**
  - Pro Micro на штыревых разъёмах или ATmega32U4 на плате;
  - модули мультиплексоров или микросхемы (SOIC/SSOP-24);
  - шаг энкодеров (20–25 мм, с кольцами больше);
  - размер платы и корпуса, крепёжные отверстия;
  - количество кнопок, нужны ли кольца сразу.
- Перед печатной платой проверить схему на макетке.

## 9. Правила для ИИ в новой ветке

- Сначала прочитать `CLAUDE.md` и этот файл.
- Новые прошивки: `firmware/<id>/<id>.ino` + `project.json` с `name_en` / `description_en`.
- Тексты интерфейса: `data-en` в HTML, `L("рус", "eng")` в JS.
- Не упоминать сторонние коммерческие контроллеры в коде и текстах.
- Пушить в `main` (если пользователь не скажет иначе для новой ветки) и проверять сборку.
- Честно писать, что проверено на железе, а что нет.
